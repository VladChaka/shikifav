# ShikiFAV

Chrome-расширение (Manifest V3) для работы со списками [Shikimori](https://shikimori.io) без открытия сайта:

- поиск аниме, манги и ранобэ прямо в popup;
- добавление в список и смена статуса в один клик;
- оценки 0–10 и кнопка «+1 эпизод» / «+1 глава»;
- календарь онгоингов: когда выходят следующие серии тайтлов из ваших списков;
- счётчик на иконке: сколько тайтлов из ваших списков ждут отметки вышедших серий;
- уведомления о вышедшей серии — по клику открывается страница тайтла на Shikimori;
- пункт контекстного меню «Найти «…» на Shikimori» для выделенного текста на любой странице.

Расширение опубликовано в Chrome Web Store — [ShikiFAV](https://chromewebstore.google.com/detail/shikifav/bpjembchapdbgncmacpkbepfjghjdkan), издатель Chaka Labs (2026-08-06). Кому нужна просто рабочая версия — ставит оттуда. Сборка из исходников остаётся для тех, кому нужна своя версия или свои правки.

Ниже — путь с нуля до работающего расширения; шаги идут по порядку, пропускать нельзя. **Сборка из исходников требует собственного OAuth-приложения на Shikimori** — это не формальность, а второй шаг, без которого вход не заработает.

## 1. Требования

| Что     | Версия            | Почему                                                                                                                  |
| ------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Chrome  | **127 или новее** | пункт контекстного меню открывает popup через `browser.action.openPopup()` — этот API доступен расширениям с Chrome 127 |
| Node.js | **≥ 20.12.0**     | требование сборщика WXT (`engines` в `node_modules/wxt/package.json`); проверялось на Node 22.20                        |
| pnpm    | **≥ 9**           | `pnpm-lock.yaml` в формате lockfileVersion 9.0; проверялось на pnpm 11.13                                               |

Ещё понадобится аккаунт на Shikimori — под ним регистрируется OAuth-приложение и выполняется вход.

В `package.json` полей `engines`/`packageManager` нет, версии выше — минимумы, вытекающие из зависимостей.

## 2. Регистрация OAuth-приложения на Shikimori

Расширение ходит в API только под своим OAuth-приложением, поэтому приложение нужно завести своё — чужие `client_id`/`client_secret` в репозитории не лежат и лежать не будут.

1. Залогиньтесь на Shikimori и откройте **https://shikimori.io/oauth/applications** → создать приложение.
2. **Имя приложения.** Запишите его дословно — это же значение пойдёт в `.env` как `WXT_SHIKI_APP_NAME`. Имя уходит в заголовок `User-Agent` каждого запроса к API: Shikimori этого требует, за запросы без осмысленного User-Agent банят по IP. Несовпадение имени приложения и `WXT_SHIKI_APP_NAME` — прямая дорога к блокировке.
3. **Scope** — только `user_rates`. Больше расширению ничего не нужно (списки, статусы, оценки, прогресс).
4. **Redirect URI** — см. следующий пункт.
5. После создания скопируйте `client_id` и `client_secret` — они пойдут в `.env` (раздел 3).

### Redirect URI зависит от ID расширения

Chrome выдаёт расширению адрес вида `https://<EXTENSION_ID>.chromiumapp.org/`, и именно он должен быть прописан в приложении на Shikimori. Точное значение всегда можно получить из самого расширения: открыть `chrome://extensions`, включить **Режим разработчика** (без него в карточке нет ни ID, ни ссылки на service worker), нажать на ссылку **service worker** в карточке расширения и выполнить в консоли

```js
chrome.identity.getRedirectURL();
```

Важно: **у production-сборки и у dev-сборки ID разные**, значит и redirect URI разные.

- **Production** (`pnpm build` / `pnpm zip`). ID определяется значением `WXT_MANIFEST_KEY` (раздел 3). Со значением `none`, которое приходит из `.env.example`, сборка идёт **без** ключа `key` в манифесте, и её ID выводится из абсолютного пути к папке `.output/chrome-mv3` — то есть у каждого свой, как у dev-сборки. Готового адреса, который можно списать отсюда, у вашей сборки нет: узнайте свой командой выше и его же зарегистрируйте. (У опубликованной версии ID `bpjembchapdbgncmacpkbepfjghjdkan` — он получается из ключа издателя, которого в репозитории нет; вписывать его себе бессмысленно и вредно, раздел 3.)
- **Dev** (`pnpm dev`). Ключ в dev-сборку не подставляется вовсе, её ID тоже вычисляется из пути к папке сборки. Узнать — командой выше в консоли service worker dev-расширения.

Поле Redirect URI у Shikimori принимает несколько адресов — по одному в строке. В приложении автора их несколько: магазинной сборки, его локальной dev-сборки и прежней prod-сборки, пока та ещё где-то установлена. Сделайте так же: адрес той сборки, которой пользуетесь, обязателен, а если будете запускать `pnpm dev` — добавьте второй строкой её адрес.

Если redirect URI не совпадёт, окно входа закончится ошибкой ещё до выдачи кода.

## 3. Файл `.env`

Секреты живут только локально. В репозитории есть шаблон `.env.example`:

```bash
cp .env.example .env
```

и заполните три переменные:

```
WXT_SHIKI_APP_NAME="имя приложения — ровно как на Shikimori"
WXT_SHIKI_CLIENT_ID="client_id из приложения"
WXT_SHIKI_CLIENT_SECRET="client_secret из приложения"
```

Четвёртая, `WXT_MANIFEST_KEY`, приходит из `.env.example` со значением `none` — это **не секрет**, а публичный ключ, фиксирующий ID расширения (раздел 2). `none` собирает без ключа: ID выводится из пути к папке, и `chrome.identity.getRedirectURL()` вашей сборки даёт адрес, который вы регистрируете в своём приложении. Ключ издателя туда не подставлен намеренно — с ним ваша сборка претендовала бы на идентификатор опубликованного расширения, и Chrome отказался бы ставить её рядом с версией из магазина. Своё значение имеет смысл вписывать, если у вас есть собственный ключ и нужен стабильный ID между машинами. Пустая или отсутствующая переменная — ошибка сборки: сборка с чужим ID выглядит рабочей и ломается только на входе.

- Префикс `WXT_` обязателен: только такие переменные WXT пробрасывает в код сборки (`src/lib/config.ts` читает их через `import.meta.env`).
- `.env*` перечислен в `.gitignore` (исключение — `.env.example`). Реальные `client_id`, `client_secret` и токены в репозиторий не попадают, и в этом README их тоже нет.
- Значения читаются **на этапе сборки**. Изменили `.env` — пересоберите расширение и нажмите «Обновить» на карточке в `chrome://extensions`.

**`client_secret` неизбежно оказывается внутри собранного расширения, и спрятать его там нельзя** — обфускацию или шифрование расширение обязано развернуть само, а значит развернёт и любой, кто его читает. Так работает любой публичный клиент, у которого нет сервера; Shikimori при этом требует аутентификацию клиента и публичные клиенты (PKCE без секрета) пока не поддерживает — живая проба в `docs/04-auth.md` §5.

Что из этого следует практически:

- **своей сборкой можно пользоваться и делиться** — но с **своим** приложением. Секрет из вашего `.env` уедет в сборку, поэтому не отдавайте её вместе с чужими `client_id`/`client_secret` и не выкладывайте свою в магазин под чужим приложением;
- **у опубликованной версии секрет тоже внутри**, и это принято сознательно. Масштаб риска разобран в `docs/06-roadmap.md`, блок «БЛОКЕР публикации»: секрет в одиночку не даёт доступа к чужим аккаунтам — обмен кода требует кода, выданного на зарегистрированный redirect URI, то есть на ID конкретного расширения. Утекает возможность представляться приложением, а не чужие данные;
- **запрос в Shikimori про поддержку публичных клиентов** подготовлен (`docs/04-auth.md` §5). Если его примут, секрет уйдёт из сборки совсем — `PKCE_ENABLED` в коде уже есть.

## 4. Сборка и установка в Chrome

```bash
pnpm i        # установка зависимостей (заодно выполнит wxt prepare)
pnpm build    # production-сборка в .output/chrome-mv3
```

Затем в Chrome:

1. Откройте `chrome://extensions`.
2. Включите **Режим разработчика** (переключатель справа сверху).
3. Нажмите **Загрузить распакованное расширение** и выберите папку `.output/chrome-mv3` (именно папку, не отдельный файл).
4. В карточке расширения появится ID. Со значением `WXT_MANIFEST_KEY=none` из `.env.example` он выведен из пути к папке `.output/chrome-mv3` и потому свой у каждого — сверьте, что redirect URI именно этого ID зарегистрирован в вашем приложении на Shikimori (раздел 2).

Расширение ставится не из магазина, поэтому Chrome помечает его как непроверенное: в `chrome://extensions` может появиться блок безопасности вида «Chrome не может проверить, откуда это расширение». Для распакованной сборки это нормально — расширение включено и работает, удалять его по подсказке не нужно.

Альтернатива — архив:

```bash
pnpm zip      # .output/shikifav-<версия>-chrome.zip
```

Учтите: **Chrome не устанавливает zip напрямую.** Архив пригоден только для переноса на другую машину — там его нужно распаковать и загрузить получившуюся папку тем же способом «Загрузить распакованное».

## 5. Первый вход

1. **Закрепите иконку в панели.** Свежеустановленное расширение Chrome в панель не выносит: нажмите кнопку **Расширения** (пазл справа от адресной строки) и щёлкните булавку рядом с **ShikiFAV**. Без закрепления popup тоже открывается — кликом по названию в том же меню.
2. Нажмите на иконку расширения — откроется popup с экраном «Войдите, чтобы управлять своими списками».
3. Кнопка **«Войти через Shikimori»** откроет отдельное окно авторизации Shikimori (стандартный OAuth-флоу Chrome, форма логина — только на сайте Shikimori, внутри расширения её нет).
4. Подтвердите доступ. Окно закроется само, в шапке popup появятся аватар и ник.
5. Дальше — вкладка **«Поиск»** (введите название; тип: Аниме / Манга / Ранобэ), вкладка **«Мои списки»** (фильтры по типу и статусу, `+1`, оценка, смена статуса) и вкладка **«Календарь»** (расписание следующих серий по вашим спискам; только аниме, ничего не меняет).

Сессия переживает перезапуск браузера: токены лежат в `chrome.storage.local` и обновляются автоматически. Повторно логиниться после каждого запуска Chrome не нужно.

## 6. Настройки

Настройки открываются отдельной вкладкой — четырьмя путями:

- кнопкой **⚙** в шапке popup (шапка появляется после входа, на экране входа её нет);
- кнопкой **♥** там же — она открывает те же настройки сразу на разделе «Поддержать»;
- из `chrome://extensions` → **Подробнее** → **Параметры расширения**;
- правым кликом по иконке расширения → **Параметры**.

Слева — четыре раздела.

**Вид**

- **Тема** — системная / светлая / тёмная. Системная берётся из браузера и системы, явный выбор действует только внутри расширения.
- **Названия** — что показывать первой строкой в карточках поиска и списков: русские или ромадзи.

**Поведение**

- **Стартовая вкладка** — с какой вкладки открывается popup: «Поиск», «Мои списки», «Календарь» или последняя открытая.
- **Статус в один клик** — какой статус ставит кнопка на карточке поиска (для манги и ранобэ подпись меняется: «Читаю», «Прочитано»).
- **Фильтры по умолчанию** — тип в поиске (Аниме / Манга / Ранобэ) и статус в «Моих списках», с которыми вкладки открываются, пока их не переключили вручную.
- **Новые серии** — два переключателя: «Счётчик на иконке» и «Уведомления». Пока счётчик включён, расширение раз в полчаса — само, без открытого popup — спрашивает у Shikimori тайтлы из «Смотрю», «Пересматриваю» и «Запланировано» и показывает на иконке, сколько из них ждут отметки. Только аниме: у манги и ранобэ дат выхода в API нет. Уведомления подчинены счётчику — пока он выключен, проверять нечего, и ряд недоступен. Клик по уведомлению открывает страницу тайтла на Shikimori: отметить серию из уведомления нельзя, фоновая половина расширения ничего не меняет в списках. Разрешение на уведомления выдаёт Chrome, а не расширение: его запрашивает отдельная кнопка **«Разрешить уведомления»** в этом же блоке, а отзывается оно в `chrome://extensions` → **Подробнее** → **Разрешения** — после отзыва блок так и напишет, что разрешения нет, а счётчик продолжит работать. Оба переключателя включены по умолчанию и требуют входа: серии считаются по вашим спискам.

**Аккаунт и данные**

- **Домен API** — `shikimori.io` (по умолчанию) или `shikimori.one`. Второй оставлен на случай очередной смены доменов Shikimori.
- **Очистить кэш** — сбрасывает кэш последнего поиска, списков, календаря и активной вкладки, а вместе с ними данные счётчика новых серий: снимок «у какого тайтла сколько серий вышло» и строки, по которым считается число на иконке. Вход и сами настройки не затрагиваются, данные на сайте не трогаются; число на иконке пересчитается ближайшим фоновым опросом.
- **Выйти** — удаляет токены, гасит счётчик на иконке и убирает уведомления расширения из системного центра, после чего возвращает экран входа. Кнопка есть только когда выполнен вход.
- **Анонимная статистика** — включена (по умолчанию) или выключена. Обезличенные события: какая вкладка открыта, что искали — аниме, мангу или ранобэ, — какие настройки меняли и какие ошибки случились. Ни аккаунт, ни списки, ни тексты запросов не уходят; полный список событий — в `PRIVACY.md`, подробнее — раздел 9.

**Поддержать**

- Настроек в разделе нет — только способы поддержать разработку и бесплатные способы помочь, всё ссылками наружу. Подробнее — раздел 9.

Внизу под разделами — версия расширения; она же в карточке `chrome://extensions`.

**Смена домена API завершает сессию.** Токен выдан приложением на конкретном домене, на другом он не действует, поэтому переключение домена делает выход — после него нужно войти заново.

## 7. Если что-то не работает

- **Окно авторизации Shikimori сразу ругается на параметры запроса.** Сборка сделана без заполненного `.env`: пустой `WXT_SHIKI_CLIENT_ID` уходит в `/oauth/authorize` как есть. Заполните `.env` (раздел 3), выполните `pnpm build` и нажмите «Обновить» на карточке расширения.
- **`401 invalid_client` при обмене кода на токен.** Неверный `client_secret` (реже — `client_id` от другого приложения). Проверьте `.env`, пересоберите, обновите расширение в `chrome://extensions`.
- **Вход не доходит до конца на `shikimori.one`.** `POST /oauth/token` на `.one` отвечает `301` на `.io`, при переходе по редиректу POST превращается в GET, и обмен кода ломается. Рабочий домен — `shikimori.io`, он и стоит по умолчанию; на `.one` без явной необходимости не переключайтесь.
- **Окно OAuth ругается на redirect URI.** ID установленного расширения не совпадает с тем, для которого зарегистрирован адрес. Посмотрите ID в `chrome://extensions`, выполните `chrome.identity.getRedirectURL()` в консоли service worker и добавьте полученный адрес в приложение на Shikimori (раздел 2).
- **Доступ отозван на сайте, а popup молчит.** Так и задумано: отзыв обнаруживается лениво. Предупреждение «Нет доступа на редактирование — войдите заново» появится после первой неудачной попытки записи (смена статуса, оценка, `+1`), а не при открытии popup. Лечится выходом и повторным входом.
- **Пункт контекстного меню открывает вкладку поиска вместо popup.** Это запасной путь: popup не удалось открыть (Chrome старше 127, нет активного окна или запрет политики). Функционально поиск работает и там.
- **Число на иконке не появляется.** Проверьте по очереди: выполнен ли вход; включён ли «Счётчик на иконке» в настройках («Поведение» → «Новые серии»); есть ли вообще невзятые серии — счётчик считает тайтлы, у которых вышедших серий больше отмеченного прогресса, и при нуле таких значок остаётся без числа. После входа или включения первый опрос идёт через минуту, а дальше раз в полчаса — мгновенного появления ждать не надо.
- **Число на иконке замерло.** Оно уменьшается сразу после `+1`, ввода номера серии, смены статуса и удаления записи, но **растёт** только со следующим опросом, то есть в пределах получаса. Добавление нового тайтла в список счётчик тоже не меняет до следующего опроса — это сознательно: счётчик обязан гаснуть вовремя, а расти может с опозданием.
- **Уведомления не приходят, хотя включены.** Нужны три вещи разом: включён счётчик (без опроса уведомлений не бывает), включены сами уведомления и **выдано разрешение Chrome** — кнопка «Разрешить уведомления» в том же блоке настроек. Если разрешение отозвано в `chrome://extensions`, блок настроек сам вернёт кнопку на место. Уведомления бывают только по аниме: у манги и ранобэ в API нет ни даты следующей главы, ни счётчика вышедших.
- **Пришло меньше уведомлений, чем вышло серий.** За один опрос показывается не больше трёх; остальные тайтлы проходят молча, а их серии видны в числе на иконке и в календаре. Так сделано, чтобы после нескольких дней без браузера не прилетала пачка из десятков сообщений.
- **Клик по уведомлению ничего не открывает.** Так бывает у уведомления, пережившего перезапуск браузера: адрес страницы тайтла живёт в сессионном хранилище и после перезапуска его нет. Уведомление просто закроется; тайтл всегда можно открыть из popup.
- **Логи.** Ошибки сети и API пишутся в консоль service worker (`chrome://extensions` при включённом **Режиме разработчика** → ссылка **service worker**). Токены и `client_secret` в логи не попадают.

## 8. Разработка

```bash
pnpm dev        # dev-сборка с HMR, поднимает Chrome с расширением
pnpm compile    # проверка типов (vue-tsc --noEmit)
pnpm lint       # eslint
pnpm test       # vitest
pnpm build      # production-сборка в .output/chrome-mv3
pnpm size       # проверка бюджета бандла (нужна свежая pnpm build)
pnpm zip        # архив для переноса
pnpm format     # prettier --write
```

`pnpm dev` ставит **отдельное** расширение с собственным ID — рядом с production-сборкой, не конфликтуя с ней. Для входа из dev-сборки её redirect URI должен быть зарегистрирован в OAuth-приложении отдельной строкой (раздел 2).

`pnpm size` разбирает уже собранный `.output/chrome-mv3` и сверяет с бюджетами из `docs/05-ui.md` четыре числа (всё в gzip): JS popup ≤ 80 КБ, CSS popup ≤ 6 КБ, CSS страницы поиска ≤ 4,5 КБ, CSS настроек ≤ 3 КБ. Размеры остальных файлов печатаются, но не проверяются. Без предварительного `pnpm build` команда завершится с ошибкой.

**`pnpm test` требует `.env`.** Тесты собираются тем же Vite, и `src/lib/config.ts` читает `WXT_SHIKI_*` через `import.meta.env`. С файлом прогон зелёный: 49 файлов, 905 тестов (2026-08-10). Без файла падают 6 файлов и 129 тестов с `APP_NAME is not configured` — код тут ни при чём. В свежем клоне и в новом git worktree `.env` не появляется сам (он в `.gitignore`), а для прогона хватает любых непустых значений — настоящие ключи нужны только для входа:

```bash
WXT_SHIKI_APP_NAME=test WXT_SHIKI_CLIENT_ID=test WXT_SHIKI_CLIENT_SECRET=test pnpm test
```

**`pnpm build` и `pnpm zip` требуют `WXT_MANIFEST_KEY`** и падают с `WXT_MANIFEST_KEY is not configured`, если переменной нет. Это сделано нарочно: без ключа сборка собирается, ставится и выглядит рабочей, а ID у неё другой — и вход ломается уже после установки, на redirect URI. `pnpm dev` переменную не читает вовсе, у dev-сборки ключа нет по замыслу.

**Ловушка `spawn-sync` закрыта, делать по ней ничего не нужно (сверено 2026-08-10):** `spawn-sync: false` уже лежит в `allowBuilds` отслеживаемого `pnpm-workspace.yaml`, рядом с `@parcel/watcher`. Симптом описан здесь на случай, если он вернётся с другим пакетом: перед запуском скрипта pnpm 11 сверяет зависимости через `pnpm install`, тот выходит с `[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: <пакет>` и кодом 1, самого скрипта не запустив, и заодно дописывает в `pnpm-workspace.yaml` строку-плейсхолдер `<пакет>: set this to true or false` — коммитить плейсхолдер нельзя, с ним падение повторится у всех. Лечится заменой плейсхолдера на `false` (или `true`, если build-скрипт действительно нужен); `spawn-sync` пришёл транзитивно через `wxt → web-ext-run → fx-runner` (запуск Firefox), и расширению его build-скрипт не нужен. Разовый обход — отключить саму сверку: `pnpm config set verify-deps-before-run false --location project`.

Иконки расширения (`public/icon/{16,32,48,128}.png`) — сгенерированные; их источник лежит в `assets/icon/` (два SVG: базовый и упрощённый для 16/32). Пересобрать после правки SVG: `scripts/icons.sh` (нужны `google-chrome` и python3 с Pillow).

Перед изменениями кода загляните в:

- `CLAUDE.md` — жёсткие правила проекта (вся сеть только из background, лимиты API, User-Agent, origin из конфига, секреты);
- `docs/` — продукт, архитектура и ADR, API Shikimori, OAuth, UI и бюджеты, roadmap (навигация по файлам — в конце `CLAUDE.md`).

## 9. Поддержать проект

Расширение бесплатное и без рекламы. Личных данных оно не собирает: списки, оценки и прогресс живут на Shikimori, токены и настройки — в браузере. Наружу уходит две вещи, и обе выключаются в настройках.

Первое — запросы к самому Shikimori. Кроме тех, что вы вызываете сами, есть фоновый: пока включён счётчик новых серий, расширение раз в полчаса спрашивает у Shikimori ваши онгоинги, даже если popup закрыт (раздел 6, «Поведение → Новые серии»). Разлогиненное расширение в фон не ходит вовсе.

Второе — анонимная статистика использования (GA4): какие функции открывают, без аккаунта, названий тайтлов и текстов запросов; фоновый опрос в неё не попадает вовсе. Она включена по умолчанию и выключается в «Настройки → Аккаунт и данные»; полный список событий — в `PRIVACY.md`. Раздел «Поддержать» — это только ссылки наружу: платёжных данных расширение не принимает ни в каком виде.

Раздел открывается кнопкой **♥** в шапке popup или четвёртым табом на странице настроек.

**Площадка приёма одна — [Boosty](https://boosty.to/chakalabs)**: разовый донат на домен и почту проекта. Уровней подписки там нет, поэтому раздел подписку и не предлагает. Способ приёма — это одна запись в `DONATION_METHODS` (`src/lib/donations.ts`), следующий добавляется такой же **одной правкой**:

```ts
{
    id: 'boosty',
    label: 'Boosty',
    hint: 'разовый донат на домен и почту проекта',
    url: 'https://boosty.to/chakalabs',
}
```

Раздел подхватит запись сам: он рисуется от данных, шаблон и строки `i18n.ts` править не нужно. Название и пояснение лежат рядом с адресом намеренно — чтобы площадка добавлялась в одном месте. Ссылкой у способа оплаты становится только `https://`-адрес; способ с любым другим адресом в разделе не показывается вовсе — площадка, по которой нельзя заплатить, не нужна (у бесплатных способов помочь наоборот: они и без ссылки остаются текстом). Единственное исключение — «Сообщить об ошибке»: там кроме `https://` разрешён один `mailto:`-адрес. Открываются все ссылки одинаково, в новой вкладке: без этого веб-обработчик почты (Gmail) уводит на форму письма саму вкладку настроек.

Бесплатные способы помочь — они же содержимое раздела:

- **оценка и пара слов в Chrome Web Store** — помогают другим найти расширение; пункт ведёт на [страницу отзывов](https://chromewebstore.google.com/detail/shikifav/bpjembchapdbgncmacpkbepfjghjdkan/reviews) расширения;
- **рассказать знакомым**, кто ведёт списки на Shikimori;
- **сообщить об ошибке** — письмом на `support@chakalabs.com`;
- **подписаться на канал в Telegram** — [@ChakaLabs](https://t.me/ChakaLabs), коротко о новых версиях.
