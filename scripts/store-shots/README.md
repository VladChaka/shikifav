# Скриншоты для Chrome Web Store

Снимают кадры 1280×800 из `store-assets/screenshots/` с **живой production-сборки**, а не с макетов. Порядок:

```bash
pnpm build
python3 scripts/store-shots/fetch-demo-data.py   # данные из публичного API
python3 scripts/store-shots/seed.py              # session-кэш для первого кадра
python3 scripts/store-shots/stub.py              # ответы API на время съёмки
python3 scripts/store-shots/capture.py           # headless Chrome → raw-*.png
python3 scripts/store-shots/compose.py           # → store-*.png 1280×800
```

Требуется `google-chrome` и python3 с Pillow. Промежуточные файлы (`demo-data.json`, `seed.json`, `stubs.json`, `raw-*.png`) появляются рядом со скриптами и в git не хранятся.

## Почему так, а не проще

- **Демонстрационный аккаунт, а не аккаунт владельца.** В кадры попадают ник, аватар и списки; поэтому ник — `shikifav`, аватар — нейтральный SVG, а тайтлы и постеры настоящие, из публичного API. Скриншот честно показывает продукт, но не выкладывает чужую личную страницу в витрину магазина.
- **Ответы API подменяются (`stub.py` + `Fetch` через CDP).** Одного session-кэша не хватает: вкладка при показе делает плановый рефреш, с фальшивым токеном он отвечает 401, и по соглашению фазы 3 экран ошибки заменяет строки. Первый кадр был бы «Сессия истекла».
- **Ключ раздела настроек ставится ПОСЛЕ загрузки страницы.** Уже открытая страница ловит `pendingOptionsSection` через `storage.onChanged` и переключается сама — если положить ключ до `reload`, первый экземпляр страницы съест его, и кадр выйдет не тот. Обнаружено при съёмке; заодно это живое подтверждение, что переключение на лету работает.
- **`ws.py` — свой минимальный клиент WebSocket.** Системная библиотека `websockets` несовместима с Python 3.10 (`Lock(loop=…)`), а ставить пакеты в окружение владельца ради скриншотов незачем.
- **Ответы на перехват отправляются без ожидания (`post`, не `call`).** Обработчик события, который сам ждёт ответа внутри насоса событий, рассинхронизирует сопоставление по `id` — на этом скрипт уже спотыкался.
- **popup 380×580 меньше требуемых магазином 1280×800**, поэтому он ставится на подложку в цвет темы; исходник снят в 2×, так что увеличение до 700 px по высоте идёт без апскейла.
