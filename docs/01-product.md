# 01 — Продукт

## Видение
Расширение для Chrome, которое позволяет управлять списками Shikimori, не открывая сайт: нашёл тайтл — в два клика добавил в «Запланировано», отметил серию, поставил оценку. Ключевое качество — скорость: popup открывается мгновенно, поиск отвечает быстрее, чем успела бы загрузиться страница сайта.

## Целевой пользователь
Один пользователь — владелец проекта, авторизуется под своим аккаунтом Shikimori. Это упрощает решения: не нужны онбординг, аналитика, миграции настроек, мультиязычность.

## Не-цели (осознанно НЕ делаем)
- Комментарии, форум, клубы, личные сообщения
- Просмотр видео / чтение манги
- Полный клон сайта: детальные страницы с описаниями, скриншотами, персонажами (максимум — компактная карточка)
- Публикация в Chrome Web Store (пока)
- Поддержка Firefox/Safari (архитектура не должна мешать добавить позже, но время на это сейчас не тратим)

## Функциональность по фазам
| Фаза | Что входит |
|---|---|
| 1 | OAuth2-вход, профиль (ник, аватар), выход |
| 2 | Поиск аниме, статус «в моём списке», добавление / смена статуса / удаление |
| 3 | Мои списки по статусам, оценка 1–10, «+1 эпизод», прогресс |
| 4 | Манга и ранобэ: поиск + списки (главы/тома вместо эпизодов) |
| 5 | Контекстное меню: поиск выделенного текста |
| 6 | Полировка: перфоманс-аудит, иконки, README, упаковка; страница настроек и тема |
| 7 | Календарь онгоингов: расписание следующих серий по моим спискам |

## User stories и критерии приёмки

Критерий отмечен, когда закрыта его фаза (docs/06 — код, ревью и ручной smoke владельца): US-1 — фаза 1, US-2 и US-3 — фаза 2, US-4…US-6 — фаза 3, US-7 — фаза 4, US-8 — фаза 5. US-9 остаётся неотмеченной: код фазы 7 готов, но smoke-чеклист владельцем не пройден и owner-verification по `nextEpisodeAt` под Bearer открыт (docs/03).

### US-1. Авторизация
Как пользователь, я хочу войти через свой аккаунт Shikimori, чтобы расширение управляло моими списками.
- [x] Кнопка «Войти через Shikimori» открывает окно авторизации сайта
- [x] После подтверждения popup показывает мой ник и аватар (данные whoami)
- [x] Сессия переживает перезапуск браузера (токены в storage, авто-refresh)
- [x] Кнопка «Выйти» очищает токены и возвращает экран входа
- [x] Если refresh не удался (токен отозван) — расширение показывает экран входа и не зацикливается

### US-2. Поиск аниме
- [x] Поле поиска с debounce ~300 мс, результаты ≤ 10 шт.
- [x] Карточка: постер, русское и оригинальное название, тип (TV/фильм/OVA…), год, оценка сайта, статус (анонс/онгоинг/вышло)
- [x] Если тайтл уже в моём списке — виден бейдж моего статуса
- [x] Состояния: пустой запрос — подсказка; ничего не найдено — явное сообщение; ошибка сети — кнопка «Повторить»

### US-3. Добавление в список
- [x] Карточка не из списка: primary-кнопка «+ Запланировано» (1 клик) и меню выбора другого статуса — с Ф6-20 статус этой кнопки задаётся настройкой `quickStatus`, по умолчанию «Запланировано»
- [x] Карточка из списка: бейдж текущего статуса, по клику — меню «сменить статус / удалить»
- [x] UI обновляется оптимистично; при ошибке — откат + тост с текстом ошибки
- [x] Статусы: запланировано, смотрю, пересматриваю, просмотрено, отложено, брошено

### US-4. Мои списки
- [x] Вкладка «Мои списки»: фильтр по статусу и типу (аниме/манга/ранобэ)
- [x] Строка: постер, название, прогресс `X / N эп.` (или глав), моя оценка
- [x] Подгрузка порциями (limit ~30, кнопка «Ещё»)

### US-5. Оценка
- [x] Для тайтла из списка можно выставить/изменить оценку 1–10, 0 = снять оценку
- [x] Оценка сохраняется через API и видна на сайте

### US-6. +1 эпизод
- [x] Кнопка «+1» у тайтлов в статусах «смотрю» / «пересматриваю»
- [x] Если после инкремента прогресс == всего эпизодов — inline-предложение «Перевести в „Просмотрено“?» (НЕ автоматически). **Уточнение 2026-07-29:** правило описывает только наше поведение — сами мы статус не пишем. Но при известном числе серий до предложения дело не доходит: Shikimori переводит тайтл в «Просмотрено» сам, и явный статус в том же запросе этого не отменяет (проверено, docs/03). Пользователю показывается тост о том, что статус сменил сервер
- [x] Для манги/ранобэ инкремент увеличивает главы
- [ ] Прогресс можно вписать числом, не набирая его кнопкой «+1» (дополнение фазы 7, запрос владельца 2026-07-28): клик по прогрессу в строке «Моих списков» → поле ввода; правило последней серии то же, что у «+1»

### US-7. Манга и ранобэ
- [x] Переключатель типа поиска: Аниме / Манга / Ранобэ (ранобэ = manga с kind light_novel/novel)
- [x] Карточки показывают тома/главы вместо эпизодов
- [x] Списки работают с target_type=Manga

### US-8. Контекстное меню
- [x] Пункт «Найти „%s“ на Shikimori» при выделении текста на любой странице
- [x] Открывает popup расширения с уже выполненным запросом (решение владельца 2026-07-27; полноэкранная страница `entrypoints/search` осталась запасным путём, если popup открыть не удалось)
- [x] Работает без открытого popup

### US-9. Календарь онгоингов
Как зритель, я хочу видеть, когда выходят следующие серии тайтлов из моих списков, чтобы не заходить на сайт за расписанием.
- [ ] Вкладка «Календарь» показывает тайтлы со статусами «Смотрю», «Пересматриваю» и «Запланировано», которые ещё выходят; тайтлы вне моих списков в календаре не появляются
- [ ] У строки виден мой статус — иначе «смотрю» и «собираюсь смотреть» в одном списке неразличимы
- [ ] Строка: постер, название (ссылка на страницу тайтла), дата и время следующей серии в моей часовой зоне, номер этой серии
- [ ] Строки сгруппированы по дням: «Сегодня», «Завтра», далее дата
- [ ] Если я отстал от эфира — видно, на сколько («вы на 5-й из 11 вышедших»)
- [ ] Онгоинг с необъявленной датой следующей серии не исчезает: он в отдельной группе в конце
- [ ] Календарь только для аниме: у манги и ранобэ в API даты следующей главы нет, поэтому выбора типа на вкладке нет
- [ ] Календарь ничего не меняет в списках: «+1», оценка и смена статуса живут во вкладке «Мои списки»
- [ ] Открытие popup на другой вкладке не порождает запросов календаря; при показе вкладки строки появляются мгновенно из кэша, сеть догоняет

## Метрики качества
- Открытие popup → интерактивность: < 150 мс (первый рендер из кэша)
- Ответ поиска после debounce: p50 < 500 мс при нормальной сети
- Ноль превышений лимитов API в обычных сценариях (ни одного 429 в smoke-тестах)
