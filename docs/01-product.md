# 01 — Продукт

## Видение
Расширение для Chrome, которое позволяет управлять списками Shikimori, не открывая сайт: нашёл тайтл — в два клика добавил в «Запланировано», отметил серию, поставил оценку. Ключевое качество — скорость: popup открывается мгновенно, поиск отвечает быстрее, чем успела бы загрузиться страница сайта.

## Целевой пользователь
Изначально — один пользователь, владелец проекта. **С 2026-07-29 решение изменилось: расширение будет опубликовано в Chrome Web Store**, то есть у него появятся сторонние пользователи. Что это меняет и что нет:
- по-прежнему не нужны мультиязычность и серверная часть — расширение работает под аккаунтом того, кто его поставил;
- **аналитика перестала быть не-целью 2026-07-30** (решение владельца, фаза 10): с выходом в магазин появились сторонние пользователи, и вопрос «чем из этого вообще пользуются» перестал решаться взглядом на собственный профиль. Ограничение осталось прежним — обезличенные события об использовании функций, без аккаунта, названий тайтлов и текстов запросов, с выключателем в настройках;
- появляется цена ошибки в чужих руках: непонятные состояния, молчаливые отказы и потеря данных теперь стоят дороже, чем «владелец разберётся»;
- появляется смысл у раздела поддержки проекта (фаза 8) и у подготовки листинга: описание, скриншоты, privacy policy, обоснование каждого permission. Подготовка листинга — отдельная фаза, не смешивается с продуктовыми.

## Не-цели (осознанно НЕ делаем)
- Комментарии, форум, клубы, личные сообщения
- Просмотр видео / чтение манги
- Полный клон сайта: детальные страницы с описаниями, скриншотами, персонажами (максимум — компактная карточка)
- ~~Публикация в Chrome Web Store~~ — **больше не не-цель** (решение владельца 2026-07-29): расширение будет опубликовано. Сама подготовка листинга вынесена в отдельную фазу
- Поддержка Firefox/Safari (архитектура не должна мешать добавить позже, но время на это сейчас не тратим)

## Функциональность по фазам
| Фаза | Что входит |
|---|---|
| 1 | OAuth2-вход, профиль (ник, аватар), выход |
| 2 | Поиск аниме, статус «в моём списке», добавление / смена статуса / удаление |
| 3 | Мои списки по статусам, оценка 1–10, «+1 эпизод», прогресс |
| 4 | Манга и ранобэ: поиск + списки (главы/тома вместо эпизодов) |
| 5 | Контекстное меню: поиск выделенного текста |
| 6 | Полировка: перфоманс-аудит, иконки, README, упаковка; страница настроек и тема |
| 7 | Календарь онгоингов: расписание следующих серий по моим спискам |
| 8 | Страница поддержки проекта: раздел в настройках, сердце в шапке popup, блок в README |
| 9 | Публикация в Chrome Web Store: листинг, скриншоты, privacy policy, обоснование permissions |
| 10 | Анонимная статистика: закрытый словарь событий GA4, выключатель в настройках |
| 12 | Связанные тайтлы: сиквелы, приквелы, первоисточник — экраном поверх вкладок popup |

Фазы 9 и 10 продуктовых историй не добавляли: девятая — про магазин, десятая — про статистику, и обе описаны в docs/06 и docs/07. Фаза 11 (уведомления и бейдж) в бэклоге и **пропущена по решению владельца 2026-08-10** — взята сразу двенадцатая; нумерация бэклога при этом НЕ сдвигается, уведомления остаются одиннадцатыми.

## User stories и критерии приёмки

Критерий отмечен, когда закрыта его фаза (docs/06 — код, ревью и ручной smoke владельца): US-1 — фаза 1, US-2 и US-3 — фаза 2, US-4…US-6 — фаза 3, US-7 — фаза 4, US-8 — фаза 5, US-9 — фаза 7 (smoke 2026-07-29), ввод номера серии в US-6 — дополнение фазы 7 (smoke 2026-07-29). US-10 — фаза 8 (smoke 2026-07-29). US-11 — фаза 12, в работе с 2026-08-10: её критерии единственные неотмеченные, у остальных историй закрыты все.

### US-1. Авторизация
Как пользователь, я хочу войти через свой аккаунт Shikimori, чтобы расширение управляло моими списками.
- [x] Кнопка «Войти через Shikimori» открывает окно авторизации сайта
- [x] После подтверждения popup показывает мой ник и аватар (данные whoami)
- [x] Сессия переживает перезапуск браузера (токены в storage, авто-refresh)
- [x] Кнопка «Выйти» очищает токены и возвращает экран входа
- [x] Если refresh не удался (токен отозван) — расширение показывает экран входа и не зацикливается

### US-2. Поиск аниме
- [x] Поле поиска с debounce ~300 мс, результаты ≤ 10 шт.
- [x] Карточка: постер, русское и оригинальное название, тип (TV/фильм/OVA…), год, оценка сайта, статус (анонс/онгоинг/вышло)
- [x] Если тайтл уже в моём списке — виден бейдж моего статуса
- [x] Состояния: пустой запрос — подсказка; ничего не найдено — явное сообщение; ошибка сети — кнопка «Повторить»

### US-3. Добавление в список
- [x] Карточка не из списка: primary-кнопка «+ Запланировано» (1 клик) и меню выбора другого статуса — с Ф6-20 статус этой кнопки задаётся настройкой `quickStatus`, по умолчанию «Запланировано»
- [x] Карточка из списка: бейдж текущего статуса, по клику — меню «сменить статус / удалить»
- [x] UI обновляется оптимистично; при ошибке — откат + тост с текстом ошибки
- [x] Статусы: запланировано, смотрю, пересматриваю, просмотрено, отложено, брошено

### US-4. Мои списки
- [x] Вкладка «Мои списки»: фильтр по статусу и типу (аниме/манга/ранобэ)
- [x] Строка: постер, название, прогресс `X / N эп.` (или глав), моя оценка
- [x] Подгрузка порциями (limit ~30, кнопка «Ещё»)

### US-5. Оценка
- [x] Для тайтла из списка можно выставить/изменить оценку 1–10, 0 = снять оценку
- [x] Оценка сохраняется через API и видна на сайте

### US-6. +1 эпизод
- [x] Кнопка «+1» у тайтлов в статусах «смотрю» / «пересматриваю»
- [x] Если после инкремента прогресс == всего эпизодов — inline-предложение «Перевести в „Просмотрено“?» (НЕ автоматически). **Уточнение 2026-07-29:** правило описывает только наше поведение — сами мы статус не пишем. Но при известном числе серий до предложения дело не доходит: Shikimori переводит тайтл в «Просмотрено» сам, и явный статус в том же запросе этого не отменяет (проверено, docs/03). Пользователю показывается тост о том, что статус сменил сервер
- [x] Для манги/ранобэ инкремент увеличивает главы
- [x] Прогресс можно вписать числом, не набирая его кнопкой «+1» (дополнение фазы 7, запрос владельца 2026-07-28): клик по прогрессу в строке «Моих списков» → поле ввода; правило последней серии то же, что у «+1»

### US-7. Манга и ранобэ
- [x] Переключатель типа поиска: Аниме / Манга / Ранобэ (ранобэ = manga с kind light_novel/novel)
- [x] Карточки показывают тома/главы вместо эпизодов
- [x] Списки работают с target_type=Manga

### US-8. Контекстное меню
- [x] Пункт «Найти „%s“ на Shikimori» при выделении текста на любой странице
- [x] Открывает popup расширения с уже выполненным запросом (решение владельца 2026-07-27; полноэкранная страница `entrypoints/search` осталась запасным путём, если popup открыть не удалось)
- [x] Работает без открытого popup

### US-9. Календарь онгоингов
Как зритель, я хочу видеть, когда выходят следующие серии тайтлов из моих списков, чтобы не заходить на сайт за расписанием.
- [x] Вкладка «Календарь» показывает тайтлы со статусами «Смотрю», «Пересматриваю» и «Запланировано», которые ещё выходят; тайтлы вне моих списков в календаре не появляются
- [x] У строки виден мой статус — иначе «смотрю» и «собираюсь смотреть» в одном списке неразличимы
- [x] Строка: постер, название (ссылка на страницу тайтла), дата и время следующей серии в моей часовой зоне, номер этой серии
- [x] Строки сгруппированы по дням: «Сегодня», «Завтра», далее дата
- [x] Если я отстал от эфира — видно, на сколько («вы на 5-й из 11 вышедших»)
- [x] Онгоинг с необъявленной датой следующей серии не исчезает: он в отдельной группе в конце
- [x] Календарь только для аниме: у манги и ранобэ в API даты следующей главы нет, поэтому выбора типа на вкладке нет
- [x] Календарь ничего не меняет в списках: «+1», оценка и смена статуса живут во вкладке «Мои списки»
- [x] Открытие popup на другой вкладке не порождает запросов календаря; при показе вкладки строки появляются мгновенно из кэша, сеть догоняет

### US-10. Поддержка проекта
Как пользователь, который поставил расширение из Store, я хочу понимать, как поддержать автора, чтобы это не приходилось искать.
- [x] В настройках есть раздел «Поддержать» со способами поддержки; каждый способ — внешняя ссылка, открывается в новой вкладке
- [x] Пока способов не заведено, раздел не выглядит сломанным: он показывает бесплатные способы помочь (отзыв в Store, рассказать знакомым, сообщить об ошибке)
- [x] В шапке popup есть иконка-сердце, открывающая этот раздел напрямую
- [x] Раздел ничего не собирает и никуда не отправляет: ни платёжных данных, ни телеметрии — только ссылки наружу
- [x] Тот же список есть в README для тех, кто ставит расширение из исходников

### US-11. Связанные тайтлы (фаза 12)
Как зритель, я хочу от найденного тайтла увидеть его сиквелы, приквелы и первоисточник, чтобы не уходить на сайт за вопросом «а что смотреть дальше» и «с чего это началось».
- [ ] У карточки в поиске и у строки в «Моих списках» есть контрол, открывающий связанные тайтлы
- [ ] Экран открывается **поверх вкладок popup**, с возвратом на то же место — вкладка браузера не открывается (обещание видения: «не открывая сайт»)
- [ ] Строка связанного тайтла: постер, название (ссылка на сайт), вид связи по-русски, год и вид, мой статус — если тайтл уже в списках
- [ ] Связанный тайтл можно положить в список и сменить ему статус прямо здесь; «+1» и оценка остаются во «Моих списках»
- [ ] Связи показываются в обе стороны по типу: у аниме виден манга-первоисточник, у манги — аниме-экранизация
- [ ] Тайтл без связей — понятное сообщение, а не пустой кадр и не ошибка: тайтлы совсем без связей нормальны (docs/03)
- [ ] Открытие popup без захода на экран не порождает ни одного запроса связей; повторное открытие того же тайтла в той же сессии popup — тоже
- [ ] Крупная франшиза (у One Piece 92 связи) открывается без заметного фриза

## Метрики качества
- Открытие popup → интерактивность: < 150 мс (первый рендер из кэша)
- Ответ поиска после debounce: p50 < 500 мс при нормальной сети
- Ноль превышений лимитов API в обычных сценариях (ни одного 429 в smoke-тестах)
