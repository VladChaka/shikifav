# 06 — Roadmap

Правила: фазы выполняются строго по порядку. Фаза закрыта = все чекбоксы + Definition of Done + smoke-чеклист пройден вручную владельцем. Пункты «Проверить при реализации» из docs/03 и docs/04 закрываются в указанных фазах с фиксацией результата в тех же файлах.

## Фаза 0 — Скелет проекта
- [x] Инициализация: `pnpm dlx wxt@latest init` (шаблон vue), TypeScript strict
- [x] ESLint + Prettier + Vitest, скрипты `compile`, `lint`, `test`
- [x] `wxt.config.ts`: имя, permissions `identity`, `storage`; host_permissions: `https://shikimori.one/*`, `https://shikimori.io/*`
- [x] Каркас: `src/lib/{config,storage,messaging}.ts`, пустой `entrypoints/background.ts`, popup «Hello» (стили — SCSS)
- [x] `.env.example` с `WXT_SHIKI_APP_NAME`, `WXT_SHIKI_CLIENT_ID`, `WXT_SHIKI_CLIENT_SECRET`; `.env*` в .gitignore (кроме `.env.example`)

**DoD:** `pnpm dev` поднимает Chrome с расширением; `pnpm compile && pnpm lint && pnpm test` зелёные.

## Фаза 1 — Авторизация (docs/04, US-1) — закрыта 2026-07-23 (smoke пройден владельцем)
- [x] Ручной шаг владельца: регистрация приложения на Shikimori, redirect URI из `chrome.identity.getRedirectURL()`, заполнение `.env`
- [x] `http.ts`: базовый fetch с origin из настроек и User-Agent; **проверка, что заголовок реально уходит** (иначе DNR-fallback из docs/03) — результат зафиксировать
- [x] `auth.ts`: login (launchWebAuthFlow → exchange → whoami), ensureToken + refresh single-flight, logout
- [x] Проверка PKCE (docs/04 §5) — результат зафиксировать
- [x] Popup: экран входа ↔ шапка с ником и аватаром; messaging `auth.*`

**DoD:** вход и выход работают; сессия переживает перезапуск браузера; при протухшем access-токене whoami сам делает refresh и отвечает без ошибки.
**Smoke:** войти → полностью закрыть Chrome → открыть → popup показывает профиль без повторного логина; выход очищает состояние и возвращает экран входа.

## Фаза 2 — Поиск аниме + управление статусом (docs/03, US-2, US-3)
- [x] Интроспекция GraphQL (типы Anime, Poster, UserRate; аргументы animes) — обновить запросы и чекбоксы в docs/03
- [x] Rate limiter в `http.ts` (4 rps / 80 rpm, backoff на 429 для GET) + юнит-тесты на fake timers
- [x] `graphql.ts`: SearchAnimes с userRate; `rates.ts`: create / update / delete
- [x] Popup «Поиск»: debounce 300 мс, отбрасывание устаревших ответов, карточки TitleCard, бейджи статуса, StatusMenu, оптимистичные апдейты с откатом

**DoD:** найти тайтл → добавить в «Запланировано» → сменить статус → удалить; каждое действие видно на сайте Shikimori (проверка вручную).
**Smoke:** 20 быстрых последовательных поисков → ни одного 429 в логе. Отозвать доступ на сайте → попытка изменить статус/оценку → предупреждение «нет доступа на редактирование» без зацикливания; предупреждение появляется только после действия, не при открытии popup (ленивое обнаружение, docs/04 §3).
