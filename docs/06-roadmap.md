## Фаза 2 — Поиск аниме + управление статусом (docs/03, US-2, US-3) — закрыта 2026-07-23 (smoke пройден владельцем)
- [x] Интроспекция GraphQL (типы Anime, Poster, UserRate; аргументы animes) — обновить запросы и чекбоксы в docs/03
- [x] Rate limiter в `http.ts` (4 rps / 80 rpm, backoff на 429 для GET) + юнит-тесты на fake timers
- [x] `graphql.ts`: SearchAnimes с userRate; `rates.ts`: create / update / delete
- [x] Popup «Поиск»: debounce 300 мс, отбрасывание устаревших ответов, карточки TitleCard, бейджи статуса, StatusMenu, оптимистичные апдейты с откатом

**DoD:** найти тайтл → добавить в «Запланировано» → сменить статус → удалить; каждое действие видно на сайте Shikimori (проверка вручную).
**Smoke:** 20 быстрых последовательных поисков → ни одного 429 в логе. Отозвать доступ на сайте → попытка изменить статус/оценку → предупреждение «нет доступа на редактирование» без зацикливания; предупреждение появляется только после действия, не при открытии popup (ленивое обнаружение, docs/04 §3). Детект отзыва работает лишь при `credentials: 'omit'` в fetch (http.ts) — иначе сессионная кука сайта маскирует отзыв токена (docs/03, отзыв доступа).

### Дополнение фазы 3 — по итогам smoke (решение владельца 2026-07-23) — закрыто 2026-07-24 (smoke пройден владельцем)
- [x] Смена статуса (и удаление) из строки «Моих списков»: StatusMenu в RateRow, как на карточке поиска; строка, чей новый статус не соответствует текущему фильтру, после подтверждения сервером уходит из списка
- [x] Фикс: изменение статуса на стороне сайта не подтягивается в открытый список (пример: досмотр последней серии на сайте авто-переводит тайтл в «Просмотрено», у нас строка остаётся в «Смотрю» до смены фильтра) — список перезапрашивается при каждой активации вкладки, а не только при смене фильтра (было: `activate()` рефрешил один раз за жизнь popup). Тот же инвариант применён к increment: серверный авто-перевод статуса на последней серии убирает строку из отфильтрованного списка

**DoD дополнения (ручной smoke владельца):** смена статуса из строки видна на сайте; удаление из строки удаляет user_rate на сайте; строка уходит из отфильтрованного списка после подтверждения; после изменения статуса на стороне сайта переоткрытие popup / реактивация вкладки показывает актуальный список без манипуляций с фильтром.

Если increment бампит не главы — переключить «+1» манги на PATCH `{chapters: progress+1}` (contingency в docs/03), результат вписать в docs/03.

**Smoke-чеклист владельца:** поиск манги и ранобэ (ранобэ не попадает во вкладку «Манга»); добавить мангу в «Запланировано» → сменить статус на «Читаю» → видно на сайте; фильтр Манга + «Читаю», «+1 глава» → сверка глав на сайте; оценка манги; US-6 на последней главе («Перевести в „Прочитано“?»); ранобэ-список отдельно от манги; регресс аниме-сценариев фаз 2–3 не сломан; ~20 быстрых поисков со сменой типа без 429.

**DoD:** сценарии фаз 2–3 полностью работают для манги и ранобэ.
