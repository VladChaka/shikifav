# 07 — Листинг Chrome Web Store

Рабочий файл фазы 9: готовые тексты, которые вставляются в форму консоли разработчика, и решения по ним. Политика конфиденциальности живёт отдельно — `PRIVACY.md` в корне (её нужно опубликовать по адресу, см. «Открытые вопросы»).

## Single purpose (одно назначение)

Магазин требует, чтобы у расширения было одно назначение, описанное одной фразой.

> Управление личными списками аниме, манги и ранобэ на Shikimori: поиск тайтлов, добавление в список, смена статуса, оценки и отметка просмотренных серий — без открытия сайта.

Всё остальное в расширении (календарь онгоингов, контекстное меню, страница настроек, раздел поддержки) обслуживает это же назначение и отдельной функциональностью не является.

## Обоснование разрешений

Формулировки для поля «Justification» по каждому пункту. Пишем по одной причине на разрешение и без общих слов — ревьюер проверяет, что разрешение действительно нужно заявленному назначению.

### `identity`
> Вход выполняется через официальную авторизацию Shikimori (OAuth 2.0) в окне `chrome.identity.launchWebAuthFlow`. Другого способа получить доступ к спискам пользователя у API нет. Разрешение используется только для этого окна; адрес электронной почты и профиль Google не запрашиваются.

### `storage`
> Хранит в браузере пользователя токены доступа Shikimori, настройки расширения и кэш последних результатов, из которого popup рисует первый кадр без запроса к сети. Данные не покидают устройство.

### `declarativeNetRequestWithHostAccess`
> Правила API Shikimori требуют, чтобы каждый запрос нёс заголовок `User-Agent` с именем зарегистрированного приложения; без него сервер блокирует доступ. Chrome не позволяет задать `User-Agent` из `fetch()` в service worker — он молча заменяет значение, — поэтому заголовок подставляется одним динамическим правилом `modifyHeaders`, действующим только на запросы к `shikimori.one` и `shikimori.io`. Выбран вариант `...WithHostAccess`, а не полный `declarativeNetRequest`: он не даёт прав сверх уже запрошенных host_permissions.

Это разрешение выглядит для ревьюера подозрительнее остальных — оно про модификацию сетевых запросов. Поэтому в обосновании важно, что правило одно, оно только добавляет заголовок и ограничено двумя доменами; при вопросах ссылаться на `src/lib/api/user-agent-rule.ts`.

### `contextMenus`
> Добавляет один пункт меню, появляющийся при выделении текста на странице: «Найти „…“ на Shikimori». По клику выделенный текст подставляется в поиск расширения.

### `host_permissions` — `https://shikimori.one/*`, `https://shikimori.io/*`
> Адреса API Shikimori, к которому обращается расширение: поиск, чтение списков пользователя и изменение статусов, оценок и прогресса. Домены сайта исторически менялись, поэтому поддерживаются оба, а действующий выбирается в настройках расширения.

### Удалённый код
> Не используется. Расширение не загружает и не выполняет код, полученный по сети; весь код входит в пакет.

## Раскрытие данных (вкладка Privacy practices)

Ответы в форме магазина. **Сверить с формулировками формы перед отправкой** — категории там периодически меняются, а неверная сертификация сама по себе нарушение правил.

- Персональные данные, данные о здоровье, финансовая информация, переписка, местоположение — **не собираются**.
- Аутентификационная информация: токены Shikimori хранятся **локально** в `chrome.storage.local` и никуда, кроме самого Shikimori, не передаются. Если форма спрашивает «collect», то есть передачу разработчику, — ответ «нет»: получателя не существует, у проекта нет серверов.
- Продажа третьим лицам, использование не по назначению, оценка кредитоспособности — нет.
- Ссылка на политику конфиденциальности — обязательна, см. «Открытые вопросы».

## Тексты листинга

**Название:** ShikiFav

**Короткое описание** (в манифесте, лимит 132 символа — сейчас 115):
> Быстрый доступ к спискам Shikimori: поиск аниме, манги и ранобэ, статусы, оценки и «+1 эпизод» без открытия сайта.

**Полное описание** — черновик, правится владельцем:

> ShikiFav открывает ваши списки Shikimori прямо в панели браузера.
>
> • Поиск аниме, манги и ранобэ — результаты приходят быстрее, чем успела бы открыться страница сайта.
> • Добавление в список и смена статуса в один клик, оценки от 1 до 10.
> • «+1 эпизод» и ввод номера серии числом, если вы досматривали несколько подряд.
> • Календарь онгоингов: когда выходят следующие серии тайтлов из ваших списков, сгруппированные по дням.
> • Пункт контекстного меню: выделите название на любой странице и найдите его на Shikimori.
> • Тёмная тема, выбор домена API и настройки поведения.
>
> Расширение работает под вашим аккаунтом Shikimori через официальную авторизацию. Оно не собирает данные, не показывает рекламу и не обращается никуда, кроме самого Shikimori.

**Категория:** предлагается «Развлечения» (альтернатива — «Продуктивность»; решает владелец).

**Язык листинга:** русский — аудитория Shikimori русскоязычная.

## Открытые вопросы (закрывает владелец)

1. **Где разместить `PRIVACY.md`.** Магазину нужен публичный URL. У проекта нет ни сайта, ни публичного репозитория. Варианты: GitHub Pages репозитория (если он станет публичным), отдельный gist, любой статический хостинг. Адрес вписывается в листинг и в саму политику.
2. **Контактный адрес** — в `PRIVACY.md` оставлено место. Магазин требует контакт для связи, и он же попадёт в листинг.
3. **Политика магазина о пожертвованиях** — перечитать по первоисточнику. Проверить автоматически не удалось: страницы правил отдаются JavaScript'ом.
4. **Категория листинга** и финальный текст полного описания.
5. **`client_secret` и ID расширения** — блокеры, разобраны в docs/06, фаза 9.
